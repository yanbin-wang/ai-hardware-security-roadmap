# AI × 芯片与硬件安全：学生研究路线与公开数据指南

面向具备机器学习、网络安全或软件分析基础，希望从公开资源进入硬件安全研究的学生。

**目标：先用公开数据或开源 RTL 完成可复现的安全研究，再根据研究主张补充硬件验证。** 本页提供选题依据与实验路线，不把模型替换、数据集规模或期刊名称当作创新性的证明。

资料核对日期：**2026-09-29**。资源链接优先指向作者、项目维护者和正式数据存储库；本次核对了资源说明及可见发布内容，未下载全部大型数据或复现全部基线。推荐程度、新问题和实施顺序是研究建议，不是已经验证的结果。

## 如何选方向

**第一步按已有能力选，第二步按数据能支持的主张缩小问题。** 代码/图学习背景优先 RTL 与木马；时序学习背景优先侧信道、PUF 或微架构；已有传感器合作条件再加大 MEMS、LiDAR 投入。

这里的“纯软件起步”指学生不用自行采集硬件数据即可开始分析、训练或验证；不代表不需要 GPU、EDA 工具、许可证或硬件知识。数据性质分为：**实测**（物理设备采集）、**设计**（RTL/网表/安全属性）、**仿真/合成**（模型或人为构造）。三者不能混写。

| 方向 | 首选资源 | 数据性质 | 纯软件起步 | 后续硬件要求 | 推荐程度 |
|---|---|---|---|---|---|
| PUF 建模攻击 | OIPUF、pypuf 实测集合 | FPGA 实测；模拟器另计 | 可以，先用小 CRP 子集 | 跨物理设备/温压泛化需补多板验证 | ★★★★☆；有 FPGA 合作可提高优先级 |
| 功耗/电磁侧信道 | ASCAD、AES_HD、Chameleon | MCU/FPGA 实测 | 可以，优先成熟小基准 | 新平台、采集条件与部署主张需验证 | ★★★★★ |
| 硬件木马检测 | Trust-Hub、HW2VEC、NOODLE | 设计及派生图；部分合成 | 可以 | 静态检测不必流片；物理检测需实测 | ★★★★★ |
| RTL/SoC 漏洞检测 | SoC Vulnerability Benchmarks、验证基准 | 设计、软件、属性 | 可以；完整系统复现有工具适配成本 | RTL 语义研究可用仿真/形式验证；物理主张另验 | ★★★★★ |
| 微架构攻击检测 | HARPY、HARPY-V、HARPY-V-GEM5 | 实测与 gem5 仿真分开 | 可以 | 跨 CPU/线上开销主张需真实平台 | ★★★★☆ |
| 功耗侧信道恶意行为检测 | PMD | Xeon 平台实测 | 可以 | 跨平台及现场误报需新增采集 | ★★★☆☆ |
| MEMS 传感器攻击 | RAiS | IMU 实测 | 可以，适合先导研究 | 新传感器与物理攻击/控制效果需实测 | ★★★☆☆；有传感器合作可提高优先级 |
| LiDAR Spoofing | 取证挑战集、SLAMSpoof | 记录点云、回放与软件仿真 | 可以，先做复现与评估 | 物理可实现性、跨雷达、闭环影响需实测 | ★★★☆☆；有 LiDAR 平台可提高优先级 |

星级综合考虑公开数据成熟度、软件起步可行性与学生完成风险，不代表方向学术价值或录用概率。

## 1. PUF 建模攻击

**研究问题。** 物理不可克隆函数（PUF）用器件差异产生 challenge–response pairs（CRP）。研究者在明确查询权限、辅助信息和预算后，学习挑战到响应的映射，评估未知挑战的可预测性及认证风险。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [OIPUF 数据与源码](https://zenodo.org/records/7995053) | 作者明确标注 FPGA 实测；1 亿条 64-bit challenges，分别配有 6 组 (64,4) 和 6 组 (64,8) OIPUF 响应；另有 Verilog、Python 模型和 Matlab 代码 | 12 组 PUF 响应不等于 12 块独立 FPGA；模拟模型产生的 CRP 须单独标记 |
| [pypuf 实测数据目录](https://github.com/nils-wisiol/pypuf/blob/main/docs/data/datasets.rst) | MTZAA20 含 4/5/6-XOR 各 1M CRP、7/8/9-XOR 各 5M CRP；AM21 含 FPGA Arbiter 与 (1,5)-Interpose 数据 | 安装包不附带所有数据，首次访问可能下载；按集合核对实例数、重复测量与编码 |
| [pypuf](https://github.com/nils-wisiol/pypuf) | PUF 模拟、攻击与评价工具 | 模拟适合控制变量与扩大预训练，不可替代真实硬件外部测试 |
| [SOI/cSOI PUF](https://github.com/yg99992/SOI_PUF) | 作者关联发布的源码和 FPGA 工程 | 工程公开不自动意味着所有论文实测 CRP 已公开 |

**纯软件如何开始。** 从一个实测集合抽取固定规模子集，复现逻辑回归或适用的经典攻击、MLP 基线，检查响应编码、类别偏置与重复挑战，再画“查询量—攻击成功率—训练成本”曲线。先学清 Arbiter 的延迟特征，不能把原始比特输入上的弱基线当作强比较。

**可做的新问题（需查最近文献确认差异）。** 少样本适配能否在严格保留的新实例上降低查询量；模拟预训练是否迁移到实测；在存在重复测量的集合上，噪声与可靠性如何影响攻击；不同架构间迁移何时有效、何时负迁移。预训练攻击器先作为可检验假设，不预设存在跨实例共享的可学习规律。

**关键评估。** 按 PUF 实例划分适配/测试，跨物理设备结论另需板卡身份；同一 challenge 的重复测量不能跨集合泄漏。报告多数类基线、预测准确率、CRP 预算、训练与推理成本；声称认证失效时补充协议与认证成功率。100–10,000 CRP 可作为预算扫描点，不是预先承诺的成果。

**后续硬件。** 公开实测数据可支持限定分布下的算法研究；跨板卡、温度、电压和老化结论需相应新测量。没有重复测量标签时，不应声称验证了可靠性攻击。

**推荐：★★★★☆。投稿方向：** HOST、TCHES/CHES、TIFS；若贡献涉及认证系统与部署安全，可考虑 TDSC。新电路结构和硅实现属于另一种工作量，不能用纯 CRP 分类代替。

## 2. Side-Channel Attack：功耗与电磁侧信道

**研究问题。** 利用密码计算的功耗或电磁泄漏恢复敏感中间值和密钥。学习模型只是攻击链的一环，最终需要展示密钥恢复效果、所需轨迹数及攻击者可获得的知识。

| 公开资源 | 内容与数据性质 | 起步建议与限制 |
|---|---|---|
| [ANSSI ASCAD](https://github.com/ANSSI-FR/ASCAD) | 实测侧信道数据及训练/评价代码；包含 ATmega8515 与 STM32 系列实现、不同密钥设置和防护版本 | 首选入口；固定密钥、变密钥、v2 不要混称同一设置；人工失同步属于派生处理 |
| [AES_HD](https://github.com/AISyLab/AES_HD) | 作者发布的实测 AES 轨迹；官方 NPZ 子集明确为 **50,000** 条 | 不能把其他扩展版数量套到这里；核对泄漏模型、字节位置与预处理 |
| [DPA Contest](https://dpacontest.telecom-paris.fr/v4/index.php) | 不同届次的实测密码实现与攻击评测资源 | 固定版本；v4 页面含实现错误说明，需阅读后选择比较条件 |
| [CHES CTF / AISY 入口](https://aisylab.github.io/AISY_docs/datasets/) | 历史竞赛实测轨迹的研究用资源入口 | 版本、下载链接及子集命名需要复核；不要混用教程中的文件名与真实内容 |
| [Chameleon](https://huggingface.co/datasets/hardware-fab/Chameleon) | CW305/Artix-7 上真实采集的功耗，包含 RISC-V 系统的隐藏措施与交错运算；数据卡链接 TCHES 2025 论文 | 适合运算定位、分段及攻击联合评估；全量数百 GB，先选一个配置 |
| [SC2026 数据](https://huggingface.co/datasets/SCA-HNUST/SC2026) / [代码](https://github.com/SCA-HNUST/2026Dataset) | 作者描述为不同距离/遮挡下 AES、SM4、Kyber 的远场 EM 数据 | 当前代码 README 标注论文尚未发表；数据预览不能证明全部条件完整可用，先核对 Files、说明和标签 |

**纯软件如何开始。** 用 ASCAD 官方设置复现一个基线，再加入 CPA/模板攻击或其适用变体作比较；保持泄漏目标、轨迹裁剪和攻击预算一致。随后只增加一个域变化，例如失同步、防护配置或采集会话。

**可做的新问题。** 跨采集条件的少样本适配；自监督表示是否降低新实现的标注成本；在 Chameleon 中同时定位加密片段并恢复密钥；在 SC2026 条件完整且协议清楚时，研究跨距离泛化。跨密码算法预训练须处理标签语义不同，不能直接拼接分类标签。

**关键评估。** 报告 guessing entropy（真实密钥的平均排名）、success rate、达到目标成功率所需轨迹数与置信区间，而非只报分类准确率。按会话/设备/密钥设置合理切分；预处理与兴趣点选择仅用训练数据。固定密钥数据上训练/攻击的设计可用于复现，但不能单凭它声称跨密钥泛化。多次轨迹平均的采集成本必须计入预算。

**后续硬件。** 基准内算法研究可直接利用公开实测轨迹；若声称跨芯片或现实远场可用，需新增设备、距离、噪声环境验证。轨迹数很大不等于设备种类很多。

**推荐：★★★★★。投稿方向：** TCHES/CHES、HOST、TIFS；完整系统级攻击与防御可考虑安全会议。基础模型路线应先证明相对小模型的迁移收益与成本合理性。

## 3. Hardware Trojan Detection：硬件木马检测

**研究问题。** 在 RTL、网表或派生图中发现恶意增加的触发器与载荷，并给出可定位、可验证的证据。它与普通设计错误不同：需要明确恶意功能、触发条件和受影响资产。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [Trust-Hub](https://trust-hub.org/) | 硬件安全基准，含木马相关设计资源 | RTL/网表是设计数据，不能统一标为硅实测；本次主页直接访问超时，下载可用性需复核 |
| [HW2VEC](https://github.com/AICPS/hw2vec) | RTL 转 AST/DFG、图表示与硬件安全任务代码和资源 | 木马与 IP 抄袭任务标签不同；先运行项目样例检查工具依赖 |
| [NOODLE](https://github.com/cars-lab-repo/NOODLE) | 多模态图/表格检测代码；含 Trust-Hub 派生资源和单独的合成数据 | 与 HW2VEC/Trust-Hub 有来源重叠，不能当作独立外部数据集 |

**纯软件如何开始。** 选择一个小型 RTL 基准，核对 clean/infected 对，再复现简单静态特征分类器和 HW2VEC 图模型。学习时序逻辑、非阻塞赋值、复位和模块连接语义，避免把 Verilog 当普通文本处理后直接解释结果。

**可做的新问题。** 未知触发机制检测；跨宿主 IP 泛化；触发器/载荷定位；变量重命名、综合与等价变换下的鲁棒性；模型不确定性驱动的人工复核；结合代码模型与仿真证据降低误报。

**关键评估。** 按宿主设计和木马家族分组切分，同一 AES 核的轻微变体不能随机散入训练与测试。报告设计级 F1、低误报率下召回、定位指标和人工复核成本；标签只到设计级时不可直接宣称有行级真值。生成的木马须能编译并验证触发/载荷，合成扩增仅来自训练侧。

**后续硬件。** 静态 RTL 检测可用仿真/形式验证支撑，无需默认流片；声称从功耗识别实体木马时需要实际测量及正常工艺变化对照。

**推荐：★★★★★。投稿方向：** HOST、TCAD、DAC/DATE/ICCAD；明确攻击防御贡献并有严谨安全评估时可考虑 TIFS/TDSC。

## 4. RTL/SoC 漏洞检测

**研究问题。** 发现权限检查、信息流、隔离、复位和软硬件交互中的安全缺陷。模型输出应包括资产、违反的属性、位置和可复现反例，不以一段解释充当漏洞证据。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [SoC Vulnerability Benchmarks](https://github.com/socsecresearch/SoC_Vulnerability_Benchmarks) | 基于 NEORV32/Ibex 的脆弱系统、C 执行环境和 FPGA bitstream | 含软件层与硬件层弱点，不全是 RTL 标签；官方最直接执行路线依赖对应 FPGA，纯软件执行可能需要移植 testbench |
| [Hardware Security Verification Benchmarks](https://github.com/HWSec-UNC/verification-benchmarks) | 开源处理器/SoC 的 SVA 属性、缺陷说明、CWE 及固定版本 | 适合属性生成与证据验证；关注子模块、工具语法和环境约束 |
| [OpenTitan](https://github.com/lowRISC/opentitan) / [Ibex](https://github.com/lowRISC/ibex) | 真实开源硬件设计与验证工程 | 不是统一标注漏洞数据集；不能把所有 issue 或修复都认作安全漏洞 |
| [Verilator](https://github.com/verilator/verilator)、[Yosys](https://github.com/YosysHQ/yosys)、[SymbiYosys](https://github.com/YosysHQ/sby) | 开源仿真、综合、形式验证工具 | 不是数据集；复杂 SystemVerilog/SVA 的支持和替代成本须先验证 |

**纯软件如何开始。** 从一个小模块、一类访问控制属性开始：读规范→复现已知失败→运行修复版→确认同一属性通过。再让 LLM 辅助生成候选属性，与人工属性和无工具 LLM 比较，不从完整 SoC 的全自动审计起步。

**可做的新问题。** 规范到安全属性的自动映射；根据反例修正断言；跨模块信任边界漏洞；对“无结果/超时/模型不支持”的正确处理；按时间划分、避免公开答案污染的漏洞发现基准。

**关键评估。** 属性编译率、非空泛有效率、已确认漏洞数量、误报、验证时间与开销。区分有界范围内未发现反例、完整证明和工具超时。将未通过属性关联到实际资产损害；检查环境假设是否把攻击行为排除了。若模型预训练可能见过公开漏洞答案，应披露污染风险并加入独立案例。

**后续硬件。** RTL 安全属性可以在明确模型和假设下用形式方法成立，不一定需要实体芯片；但启动链、外设时序、物理泄漏或真实系统利用主张需要相应平台验证。

**推荐：★★★★★，但硬件语义与验证门槛高于普通代码分类。投稿方向：** TCAD、HOST、DAC/DATE/ICCAD；以系统安全为核心时考虑 TDSC、安全会议。

## 5. Microarchitectural Attack Detection：微架构攻击检测

**研究问题。** 从硬件性能计数器（HPC）、执行统计或时序中区分攻击和正常程序，重点验证未知攻击、不同工作负载与平台变化下的低误报检测。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [HARPY](https://doi.org/10.34810/data1982) | x86 硬件攻击与正常执行的性能计数器记录 | 适合程序运行级检测；需核对 CPU、补丁与采样条件 |
| [HARPY-V](https://doi.org/10.34810/DATA2538) | RISC-V 真实处理器上的计数器记录；[作者论文](https://link.springer.com/article/10.1186/s42400-026-00662-8)说明 V2 与 Xuantie C910 采集 | 真实硬件版本，与 gem5 版本分开；各版本程序数不能混用 |
| [HARPY-V-GEM5](https://doi.org/10.34810/data2711) | gem5 O3 CPU 的 RISC-V 攻击性能/指令计数器 | **仿真数据**，不能用它单独证明真实 CPU 部署效果 |

访问状态：上述 DOI/官方记录可被检索或由作者论文确认，本次直接打开 CORA 数据页返回网关错误，未检查实际文件和许可证。学生应先确认可下载再正式排期。

**纯软件如何开始。** 下载实测集合后，以统计特征+随机森林为基线，再做一个时序模型。按完整程序执行划分数据，然后在各集合内部切窗口；先确认模型没有只识别程序身份。

**可做的新问题。** 留一攻击家族测试；只用良性数据训练；有限计数器预算下的检测；负载混合及概念漂移；有配对条件时探索仿真到真实迁移。x86 与 RISC-V 事件定义不同，不能直接视作同名通道拼接。

**关键评估。** 未知攻击召回、每小时误报、检测延迟、采样/推理开销。随机窗口划分产生的高准确率不能证明未知程序泛化。公开轨迹离线推理时间不等于完整线上监测开销。

**后续硬件。** 数据研究不用购买采集卡；部署验证通常需可控的真实 CPU、计数器权限和明确的补丁配置。跨 CPU 结论需多型号实验。

**推荐：★★★★☆。投稿方向：** TDSC、TIFS、HOST、HASP；体系结构贡献充分时再考虑体系结构类会议。

## 6. Power Side-Channel Malware Detection：功耗侧信道恶意行为检测

**研究问题。** 在不读取程序内容的情况下，从功耗变化发现恶意运行行为，并排除正常高负载导致的混淆。该任务利用物理测量，区别于上一节的处理器内部计数器。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [PMD Dataset](https://github.com/SLAM-Lab/PMD-Dataset) | Intel Xeon D-1539 平台实测；通过电流传感器和示波器以 2 kHz 采集；CSV 时序，CC-BY-4.0 | 含多种良性负载组合及 Meltdown、Spectre、L1-cache covert channel；不是覆盖海量真实恶意软件家族的通用语料 |

**纯软件如何开始。** 解析文件名里的负载状态与攻击标签，按完整记录分组；复现统计特征+随机森林、1D-CNN，再做留一负载组合实验。不要把文件名本身送入检测器。

**可做的新问题。** 未见负载下的攻击检测；正常高功耗与恶意行为区分；低采样率下的鲁棒性；稀疏攻击的定位与拒识。恶意软件家族泛化需要补充真正多家族数据，现有标签不足以支持。

**关键评估。** 每小时误报、攻击检测延迟、按负载分层的召回，以及功耗归一化是否泄漏测试信息。重叠窗口不能跨集合；仅在三类攻击上成功时，结论也应限定在该范围。

**后续硬件。** 起步无需执行恶意代码；跨机器、功耗管理策略和传感器条件的结论需要新的受控实测。新增采集应在授权隔离实验环境进行。

**推荐：★★★☆☆，适合小规模方法验证，数据外推能力是主要瓶颈。投稿方向：** HASP、HOST；系统性证据充分再考虑 TDSC/TIFS。

## 7. MEMS Sensor Attack：惯性传感器攻击检测

**研究问题。** 声学等物理输入可能干扰 MEMS 惯性传感器，导致陀螺仪输出或状态估计异常。研究重点是区分正常运动与恶意扰动，并评估导航影响。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [RAiS Dataset](https://github.com/cmsahu97/RAiS-dataset) | VN100 受攻击 IMU、Xsens MTi-700 参考；作者提供静态/动态情境下的惯性测量与攻击标签 | **真实设备采集**；不能因有多个文件就声称包含多个受攻击传感器型号 |

**纯软件如何开始。** 确认单位、时间戳、攻击区间与参考数据同步；用频域特征+简单分类器、1D-CNN/TCN 复现，再在不同采集场景间测试。频域分析应尊重采样率，低频输出记录不等于记录了原始超声波波形。

**可做的新问题。** 仅用正常运动训练的攻击检测；静态到动态迁移；弱扰动检测与置信度；攻击检测和姿态恢复联合建模；攻击与自然振动、传感器故障的区分。若原数据没有故障对照，最后一项需新增数据。

**关键评估。** 按完整采集序列/实验轮次切分，再切窗口。报告误报/小时、延迟和攻击强度分层表现。参考 IMU 用于构造真值时，不应默认部署也能访问它；若方法使用双传感器，应明确硬件条件。

**后续硬件。** 公开数据可完成算法先导；跨型号、实际物理干扰与机器人闭环影响需要新实验。没有真实姿态/轨迹真值时，不应把分类提升表述为导航恢复提升。

**推荐：★★★☆☆；有 MEMS/机器人实验伙伴时更合适。投稿方向：** TIFS、TDSC、IoTJ；方法与系统贡献匹配时考虑 TCYB 或机器人/传感类刊会。

## 8. LiDAR Spoofing：激光雷达欺骗检测

**研究问题。** 检测异常点注入、遮蔽/点移除、位移及其对感知定位的影响。必须区分软件修改点云、受物理约束的攻击仿真和真实光学攻击。

| 公开资源 | 内容与数据性质 | 使用注意 |
|---|---|---|
| [LiDAR Spoofing Forensics Datasets](https://github.com/Allenpandas/LiDAR-Spoofing-Forensics-Datasets) | 作者描述为攻击记录点云的取证挑战，分 blackout、shift、noise 三类 | 每类任务说明只有 3 个受攻击 PCD；适合取证/复现，不足以单独支撑大规模监督训练。逐帧标签、采集及物理生成细节须核对 |
| [SLAMSpoof](https://github.com/Keio-CSG/slamspoof) / [论文](https://arxiv.org/abs/2502.13641) | 定位攻击研究代码、示例 rosbag 与点云攻击仿真流程 | 软件回放/仿真可起步；作者物理实验结论不能自动转移到学生的新方法 |

**纯软件如何开始。** 可视化挑战序列，复现几何/时序一致性检测；按 SLAMSpoof 文档回放一个示例并比较轨迹变化。先检查标签可得性，若缺完整攻击帧真值，先做人工审计而非直接声称监督评估。

**可做的新问题。** 未知攻击检测；跨场景时序一致性；检测与 SLAM 置信度联合使用；对雨雾、稀疏反射等良性变化的误报控制；满足物理注入限制的防御评估。跨 LiDAR 研究必须实际拥有不同雷达的数据。

**关键评估。** 按完整场景/轨迹划分；报告攻击帧检测、误报、检测延迟，以及存在可靠真值时的定位误差。人工注入点数、可作用角度和距离应有物理依据，不能用任意点云扰动证明远程光学攻击成立。

**后续硬件。** 算法原型无需雷达；真实光学可实现性与车辆/机器人闭环安全需受控实测。通用点云检测结果不能直接宣称适用于 SPAD 单光子事件或芯片级 ToF 链路。

**推荐：★★★☆☆；有雷达/机器人平台时可优先推进。投稿方向：** TIFS、TDSC、IoTJ；定位和机器人系统贡献可考虑 ICRA/IROS，系统安全证据充分时考虑安全会议。

## 建议优先启动的三个课题

以下是可检验的开题草案，需先完成最近相关工作对照，不能直接标成“首次”。

| 课题 | 最小可交付结果 | 核心假设与比较 | 继续/转向条件 |
|---|---|---|---|
| A. 带反例证据的 RTL 安全属性生成 | 一个已知漏洞及其修复的可运行验证流程 | 工具反馈能否相对无反馈 LLM，提高非空泛有效属性率并减少误报 | 若只提高文字解释、无法产生有效反例，收缩到一类属性 |
| B. 查询预算受限的 PUF 实例适配 | 一个公开实测集合上的预算曲线与实例分组清单 | 预训练是否优于同预算从零训练及经典攻击 | 若没有足够独立实例，先做数据效率，不宣称跨设备通用攻击 |
| C. 侧信道跨条件少样本适配 | ASCAD 基线和一个独立条件测试 | 迁移能否降低达到同一密钥恢复成功率的轨迹成本 | 若收益仅来自额外训练预算，重新设计公平比较；不要立即扩大模型 |

没有硬件合作时优先 A/C；已有可获取多板数据的合作条件时推进 B。MEMS/LiDAR 可以作为第二阶段联合课题，先落实数据和实验平台。

## 统一实验规范与八周起步计划

### 所有方向都要遵守的实验约束

1. **先写威胁模型。** 攻击者能看到什么、控制什么、调用多少次；防御者部署时能取得哪些信号。
2. **先划分再加工。** 以设备、设计家族、程序执行或采集会话分组，随后切窗、增广和归一化。随机窗口切分只作为明确标记的同分布实验。
3. **来源去重。** 原始数据及其派生图/合成增强保持同组；留出测试集不得进入无监督预训练，除非明确研究的是传导式设置。
4. **比较要公平。** 简单基线、领域经典方法、近期强方法都应有；对齐训练数据、查询预算、调参预算和可用辅助信息。
5. **报告安全效果。** 密钥恢复、有效反例、未知攻击、低误报、系统损害和部署开销，比孤立 Accuracy 更接近安全问题。
6. **结果可追溯。** 保存数据版本/DOI、校验和、切分清单、随机种子、依赖、硬件条件和运行日志；对多个种子或独立测试单位报告不确定性。
7. **主张与证据一致。** 仿真不叫实测；PUF 实例不自动等于物理设备；无标签开源工程不叫标注漏洞集；检测到已知案例不等于发现新漏洞。

### 建议排期（不是论文完成承诺）

| 阶段 | 工作 | 验收结果 |
|---|---|---|
| 第 1 周 | 选一个任务，读源论文和数据说明，下载小样本 | 一页问题定义；数据/许可证/标签/设备清单；明确不可支持的结论 |
| 第 2 周 | 复现官方或经典基线 | 可重复运行及与原结果差异说明；失败时先解决复现，不加模型 |
| 第 3–4 周 | 建立分组切分，排查泄漏，做错误分析 | 同分布与跨域结果、主要失败模式、最近工作差异表 |
| 第 5–6 周 | 只验证一个机制假设 | 与等预算基线比较、消融、训练/部署成本 |
| 第 7–8 周 | 外部测试、负结果与证据整理 | 可复现报告；继续/转向决策；确有必要时提出硬件采集计划 |

建议每名学生交一页开题卡：**资产与威胁、资源版本、独立测试单位、最强基线、唯一核心假设、成功指标、所缺证据、八周停止条件**。先做一个方向，不要求把八类数据合成一个“大模型”。

## 投稿定位

方向章节中的刊会是选题定位建议，不是录用保证，也不代表已经核实了当年的全部征稿要求。提交前按最终贡献与当届官方范围复核。

| 贡献中心 | 建议考虑 | 需要体现的证据 |
|---|---|---|
| 密码实现泄漏与攻击方法 | [TCHES/CHES](https://ches.iacr.org/2025/cfp_ches2025_v3.pdf)、HOST | 现实攻击条件、密钥恢复、严格成本比较 |
| 检测、取证与信息安全 | [TIFS](https://signalprocessingsociety.org/publications-resources/ieee-transactions-information-forensics-and-security) | 清晰安全问题、方法贡献及充分安全评估 |
| 安全系统与可信运行 | [TDSC](https://www.computer.org/digital-library/journals/tq/tdsc-topics) | 系统假设、攻击防御、部署效果与开销 |
| RTL 验证、综合、测试及安全 EDA | [TCAD](https://ieee-ceda.org/publications/tcad)、DAC/DATE/ICCAD | 自动化方法、工具链、可验证正确性与规模扩展 |
| 传感器、机器人与物理系统安全 | IoTJ、ICRA/IROS，或对应安全刊会 | 真实感知/控制任务影响，必要时有物理与闭环实验 |

安全会议如 IEEE S&P、USENIX Security、CCS、NDSS，通常应在具备完整系统安全贡献时考虑。不要把“公开数据 + 换一个网络”包装成跨领域突破；也不要默认纯算法研究需要按 ISSCC/JSSC 的芯片设计范式流片。
